# 自研设计结论

Open Workflow 自己实现场景模型、SVG 绘制、编辑交互、布局、撤销历史和格式转换。本文记录研究形成的设计原则及其在本项目中的落实方式；具体接口和兼容范围分别见 [架构说明](ARCHITECTURE.md) 与 [格式说明](FORMATS.md)。

## 统一场景，独立交互

流程图、自由白板和代码图表共用形状、连线、文字、笔迹和图片等基础元素。文档保存稳定 ID、世界坐标、样式和关系，视口平移、缩放、临时选框及光标不写入文件。格式转换与图表编译都生成这套场景，不为不同来源维护另一套编辑器。

模块分别负责文档校验、纯几何计算、交互控制、SVG 绘制、历史、存储和格式转换。编辑器与图像导出使用相同的几何、文本转义和外观规则，让同一文档在预览与导出中保持一致。

## 连线绑定稳定 ID

连线端点可以绑定节点 ID，也可以保存自由坐标。绑定后的可见端点由几何层根据最新节点轮廓计算，移动或缩放节点后重新求交。不同形状使用各自的边界，吸附距离按屏幕像素换算，不依赖节点外接矩形或缩放倍率。

多个对象一起移动时，同一次手势只应用一次位移；绑定连线通过节点计算位置，避免节点和连线重复偏移。显式端口、类图装饰端标等未具备动态绑定的图元，需要在相应结果中提示限制，不能暗示其具有自动重排能力。

## 一次操作形成一条历史

画布按下时保存操作起点，移动中更新本地预览，结束时提交一次变更。取消操作恢复起点，不产生历史。选择、悬停和视口变化不占用文档撤销；内容未变更时不重复入栈，也不清空重做。

保存、导出和切换文档前先提交正在进行的文字、属性或手势编辑。文件保存以调用时的快照为准，异步写入期间的新修改仍显示为未保存。本地草稿状态和磁盘文件状态分开记录。

## 兼容以实际结构为边界

图形 XML 先读取节点与 ID，再连接边；白板 JSON 按元素类型转换；文本图表先解析语法，再布局和绘制。既有扩展名、协议标记和字段值属于互操作契约，保留它们以继续读取已有文件。

转换只声明实际支持的结构。未知形状、复杂分组、路由、裁剪或样式需要明确提示或拒绝，不能在丢失内容后报告完全成功。导入原文随文档保留，可独立取回，但后续编辑不合并回这份原文。原生保存使用带版本并经过校验的 `.owflow` 格式。

## 代码图表生成真实几何

解析器支持明确的 22 类语法子集，保留原始行号并对未知指令报错。关系图使用节点和边；饼图、柱线图、甘特图、桑基图、雷达图和矩形树图分别按数值生成扇区、坐标、时间条、流带、径向投影及面积划分，不用同一套流程节点替代不同图表。

源码是代码图表文档的事实来源。可编辑副本保留生成后的普通图元，允许拖动和修改，但不承诺反向生成源码或继续按数据重算。需要更新统计值或语义布局时，应修改源码后重新生成。

## 用交互验证设计

验证重点包括节点移动后的连线跟随、缩放后的命中和拖动、一次手势一次撤销、取消操作不污染历史、复制后的绑定重映射、删除节点后的连线处理、草稿恢复、导入失败隔离及支持范围内的格式往返。

图表还需校验数据含义、日期和依赖、错误行号、几何比例、保存回读及 SVG 输出。真实浏览器交互用于检查静态分析和纯逻辑测试无法证明的绘制、焦点、指针及文件操作行为。
